Authorization (now admin-only, as you chose)

Every finance route except the currency list now requires the administrator role. That covers ledger, journals, periods, tax codes, payables and reports.
Four other areas are admin-only too:
invoice issue
customer payments, both list and create
stock adjustments and product price writes
project profitability
Time-entry cost snapshots are hidden from non-admins.
ApiAccessPolicyTest.php pins the required role of every API route. A new route fails the test until someone classifies it.
On the frontend, session.ts reads the role from the JWT, so non-admins no longer see the Finance menu or trigger the payments and profitability calls that would now return 403. This only hides controls; the API enforces access.
I did not tighten warehouse and supplier setup, purchase orders, receipts, dispatch, returns or invoice draft edits. They are still open to any signed-in user. I also did not review audit logging or add per-client or per-project access.
Single organization

SingleOrganizationGuardTest.php checks that a second settings row can't be stored. Business records still have no organization ownership, so multi-organization use stays unsupported.
Backups

The scripts in docker/backup/ do an encrypted daily dump of the database and uploaded documents to an off-host remote. They prune sets older than 35 days, and a separate script restores into a scratch database.
The service is a compose backup profile, so a normal docker compose up is unaffected.
docs/BACKUP.md has the setup steps and the quarterly restore-test log.
It is not operational until you configure an off-host remote and record a passing restore test. I haven't run the scripts.
